# Менеджер Задач (RSTechAppTest)

Кроссплатформенное десктопное приложение для управления списком задач, разработанное на платформе **Avalonia UI 12** с использованием **Entity Framework Core 9** и СУБД **PostgreSQL**.

---

## 🏗️ Краткое описание архитектуры

Приложение строго следует паттерну **MVVM** и принципам разделения обязанностей (SoC):
* **Domain Layer (Модели):** Сущность `TaskItem`, описывающая структуру задачи в памяти и БД.
* **Infrastructure Layer (База данных):** Контекст `AppDbContext`, паттерн Repository (`PostgresTaskRepository`) для инкапсуляции запросов и фабрика `AppDbContextFactory` для генерации миграций.
* **Presentation Layer (Интерфейс):** Представления XAML (Avalonia UI 12) и реактивные ViewModels на базе `CommunityToolkit.Mvvm` с автоматической кодогенерацией (Source Generators).
* **DI / IoC Container:** Инициализация зависимостей через `Microsoft.Extensions.DependencyInjection` с разграничением жизненных циклов объектов (`Scoped` для контекста БД, `Transient` для окон и ViewModels).

## 🚀 Как собрать и запустить

### 1. Настройка конфигурации (INI)
В папке проекта `RSTechAppTest` найдите файл **`config.ini`** и укажите реквизиты доступа к вашему локальному серверу PostgreSQL:
```ini
[Database]
Host = "ВАШ_ХОСТ"
Port = ВАШ_ПОРТ
Database = "rtech_tasks_db"
Username = "ВАШЕ_ИМЯ_ПОЛЬЗОВАТЕЛЯ"
Password = "ВАШ_ПАРОЛЬ"
```

### 2. Сборка и запуск приложения
Откройте терминал в корневой папке решения (где находится файл `.sln`) и выполните команду:
```powershell
dotnet run --project RSTechAppTest/RSTechAppTest.csproj
```

## 🔄 Как применить миграции

В проекте реализовано **два альтернативных способа** развертывания схемы базы данных:

1. **Автоматически при старте приложения (Рекомендуемый):** В коде инициализации главного окна прописан асинхронный вызов `await db.Database.MigrateAsync()`. При первом запуске через `dotnet run` приложение само обнаружит ваш сервер PostgreSQL, создаст базу данных `rtech_tasks_db` и развернет таблицу задач.
2. **Вручную через консоль .NET CLI:** Вы можете принудительно обновить базу данных до запуска приложения, выполнив команду из корня решения:
   ```powershell
   dotnet ef database update --project RSTechAppTest/RSTechAppTest.csproj
   ```
   *(Также в корне репозитория прикреплен готовый файл структуры и данных `database_dump.sql` для ручного импорта через pgAdmin/DBeaver).*

## 📊 Выполнение требований ТЗ

### ✅ Выполненные требования:
* **Стек технологий:** Проект полностью написан на C# с использованием фреймворка Avalonia UI и ORM Entity Framework Core.
* **СУБД PostgreSQL:** Интегрирован провайдер `Npgsql.EntityFrameworkCore.PostgreSQL`. 
* **Асинхронность:** Все IO-операции работы с данными (чтение, добавление, обновление, удаление) реализованы через `async/await`. Вызов миграций изолирован в фоновом потоке, что исключает зависание (deadlock) UI-потока Avalonia.
* **Паттерн MVVM и Dependency Injection:** Слои строго разделены, зависимости регистрируются через официальный IoC-контейнер .NET.
* **Валидация:** Реализована проверка входных данных (запрет пустых задач, ограничение длины заголовка до 100 символов) с выводом уведомлений в статус-бар интерфейса.
* **Модульное тестирование:** Логика валидации, пустых строк и фильтрации данных полностью покрыта Unit-тестами на фреймворке **xUnit** с использованием изолированной базы данных в оперативной памяти (`InMemoryDatabase`).

### ℹ️ Примечания по архитектурным противоречиям в ТЗ:
В исходном тексте задания содержалось техническое несоответствие: в требованиях к стеку была указана СУБД **PostgreSQL**, но в описании файловой структуры проекта упоминалось хранение в локальном файле `tasks.db` и класс `LiteDbTaskRepository` (что характерно для встроенных СУБД SQLite или LiteDB). 
* **Решение:** Проект реализован на  **PostgreSQL**, параметры подключения к которой вынесены в `.ini` файл.
